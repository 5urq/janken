# じゃんけん Webアプリケーション (janken)

情報システム応用演習（devex）個人演習 課題リポジトリ

---

## 概要
本アプリケーションは、Spring Boot、Thymeleaf、Spring Securityを用いたマルチユーザ対応のじゃんけんWebアプリケーションです。

- **第2回**: MVCパターンに基づくHTTP GET / POSTリクエスト処理の実装（フォームからのユーザ名送信、クエリパラメータによる手の選択、勝敗判定モデル `Janken.java` の実装）
- **第3回**: 
  - **Task 1 (認証・認可)**: Spring Securityを用いたフォームログイン、BCryptハッシュ化パスワードによる `user1` / `user2` の認証、`/janken/**` URLの認可保護、ログアウト処理
  - **Task 2 (DIとオブジェクト共有)**: SpringのDIコンテナ（`@Component` / `@Autowired`）を活用した `Entry.java` によるシングルトン管理。全ログインユーザ情報のリアルタイム共有および人数表示

## 【生成AIの活用と学習・理解に関する注記】

本プロジェクトの実装にあたっては、講義の実施方針（*「重要なのは演習内容を通じてSpringbootを深く理解することです。そのためであればチームで相談しても生成AIを利用しても何をしても構いません」*）に基づき、**生成AI（ペアプログラミング）**を活用してコードを作成・整備しました。

単にコードを自動生成するにとどまらず、解説用ドキュメント（`explanation.html`）の作成やAIとの対話を通じて、受講生自身が以下の動作原理をしっかりと理解した上で実装・検証を行っています：

1. **Spring Security フィルタチェーンと認証・認可の違い**:
   - `InMemoryUserDetailsManager` と BCryptアルゴリズムによるパスワードの秘匿化
   - `SecurityFilterChain` における特定エンドポイント（`/janken/**`）の保護と `permitAll()` の制御
2. **Dependency Injection（DI）とシングルトンBeanの本質**:
   - 通常の `new`（リクエストごとに新規生成・破棄され他のユーザ情報を参照できない）と、`@Component` によるDI管理（アプリケーション全体で唯一のインスタンスが共有される）の挙動の違い
3. **ThymeleafとSpring Securityの連携**:
   - `Principal` を介したログインユーザ名の取得と、共有オブジェクト（`Entry`）内のリスト展開

## 動作確認（受入条件 AC）

1. `http://localhost:8080/` にアクセスし、「jankenへのGETをリクエスト」をクリック
2. ログイン画面にて `user1` / `isdev`（または `user2` / `isdev`）でログイン
3. ログイン後、`janken.html` にてログインユーザ名、エントリー中の全ユーザ一覧、およびエントリー人数が表示されることを確認
4. 別ブラウザ（シークレットウィンドウ）で `user2` としてログインした際、両画面で `user1` と `user2` の両方が共有されて表示されることを確認（DIの動作確認）
5. ログアウトリンクをクリックし、ログアウト確認後にトップページへ戻ることを確認
