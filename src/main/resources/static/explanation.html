じゃんけんアプリの構造と役割 徹底解説

「なぜこのコードが必要なのか？」をレストランの例えで理解する

1. 全体像を「レストラン」に例えると？

Webアプリケーション（Spring Boot）は、「役割分担されたチーム」で動いています。これをレストランに例えると直感的に理解できます。

① 玄関・メニュー表
static/index.html
注文を書き込む用紙
② ウェイター（給仕係）
JankenController.java
注文を受け取り各所へ指示
③ 専門シェフ（調理場）
Janken.java (Model)
勝敗判定などの頭脳作業
④ 盛り付けとお皿
templates/janken.html
料理を盛り付けて客に見せる
💡 レストランでの注文の流れ
  1. お客さん（ブラウザ）が 玄関のメニュー表（index.html） で名前を書いて注文ボタン（POST）を押す。
  2. ウェイター（Controller） が注文票を受け取り、「新規客の案内だな」と判断。
  3. 客が「グーを出したよ！」と伝えると、ウェイターは 専門シェフ（Model: Janken） に「相手の手を決めて勝敗を判定してくれ！」と依頼。
  4. シェフが作った料理（結果データ）を、ウェイターが 盛り付け係（View: janken.html） のお皿に乗せてお客さん（ブラウザ）に提供する。

2. static/index.html の役割（玄関・注文用紙）

誰でも直接アクセスできる静的なHTMLファイルです。ユーザーに名前を入力してもらい、アプリの入り口となります。

<!-- 参加フォーム: POSTリクエストで /janken に送信 -->
<form action="/janken" method="post">
  <input type="text" name="userName" placeholder="ユーザ名を入力" required>
  <button type="submit">参加</button>
</form>
💡 なぜ POST（method="post"）を使うのか？
  • GETは「絵はがき」：URLの末尾（?userName=taro）に丸見えで届きます。
  • POSTは「封筒」：データが封筒の中（リクエスト本文）に隠されて届くため、URLが汚れず、新規登録やゲーム参加などの「状態を変えるリクエスト」に適しています。

3. JankenController.java の役割（司令塔・ウェイター）

ブラウザから届いたリクエスト（URLや送信データ）を交通整理し、「次に何をすべきか」を采配します。

① 直接URLを叩かれたときの処理（Task 1 [AC2] 対策）

// ブラウザから GET /janken で直接呼ばれた場合
@GetMapping("/janken")
public String jankenGet() {
  // ユーザ名は何もお皿（Model）に乗せずに画面だけ返す
  return "janken.html";
}

👉 ここがポイント: 新しいタブで直接 /janken を開かれたときは、userName を一切渡さずに janken.html を返します。これにより「Hi ???? が表示されない」という受け入れ基準（AC2）をクリアします。

② フォームから参加したときの処理（Task 1 [AC1] 対策）

// index.html のフォームから POST /janken で送られた場合
@PostMapping("/janken")
public String jankenPost(@RequestParam String userName, ModelMap model) {
  // 封筒から名前を取り出し、お皿（model）に乗せる
  model.addAttribute("userName", userName);
  return "janken.html";
}

👉 @RequestParam String userName: フォームの <input name="userName"> で送られた文字を受け取る仕掛けです。
👉 model.addAttribute("userName", userName): Thymeleaf（お皿）へ渡すために登録しています。

③ グー・チョキ・パーを押したときの対戦処理（Task 2 [AC] 対策）

@GetMapping("/jankengame")
public String jankenGame(@RequestParam String hand,
                         @RequestParam(required = false) String userName,
                         ModelMap model) {
  // 1. シェフ（Model）に頼んでじゃんけん勝敗を計算してもらう
  Janken janken = new Janken(hand);
  
  // 2. 結果をお皿に乗せる
  model.addAttribute("janken", janken);

  // 3. ユーザ名があれば引き続きお皿に乗せておく
  if (userName != null && !userName.isEmpty()) {
    model.addAttribute("userName", userName);
  }
  return "janken.html";
}

4. Janken.java の役割（専門シェフ・ビジネスロジック）

データの保持と、計算処理（ロジック）に特化したクラスです。

💡 なぜ Controller に全部書かずに、わざわざ分けるのか？

もしウェイターが厨房に入って魚をさばき始めたら、店は大混乱します。
「注文を受け取る係（Controller）」と「料理を作る係（Model）」を分けることで、コードが綺麗になり、後からCPUの出し方を変えたりルールを追加したりするのが圧倒的に楽になるからです（これがいわゆるオブジェクト指向とMVCの基本です）。

public class Janken {
  private String myHand;  // 自分の手
  private String cpuHand; // 相手の手
  private String result;  // 結果（勝ち/負け/あいこ）

  public Janken(String hand) {
    this.myHand = hand;

    // 🎲 CPUの手をランダム（0:グー, 1:チョキ, 2:パー）で選ぶ
    String[] hands = {"グー", "チョキ", "パー"};
    Random random = new Random();
    this.cpuHand = hands[random.nextInt(3)];

    // ⚖️ 勝敗の判定ロジック
    if (this.myHand.equals(this.cpuHand)) {
      this.result = "あいこ";
    } else if (/* 自分が勝つパターン */) {
      this.result = "勝ち";
    } else {
      this.result = "負け";
    }
  }

  // Thymeleafがお皿から値を読み取るための Getter が必須
  public String getMyHand() { return myHand; }
  public String getCpuHand() { return cpuHand; }
  public String getResult() { return result; }
}

5. templates/janken.html の役割（盛り付け・画面表示）

Javaから渡されたデータ（Model）を、Thymeleafというテンプレートエンジンを使ってHTMLに埋め込みます。

① ユーザ名があるときだけ表示（`th:if`）

<!-- userName が model に入っている時だけ、このタグが出現する -->
<div th:if="${userName}">
  <h2>Hi [[${userName}]]</h2>
</div>

👉 直接アクセスされたときは userName が空なので、この <div> 自体が完全に非表示になります！

② じゃんけんの手のリンク

<div class="hand-links">
  <a th:href="@{/jankengame(hand='Gu', userName=${userName})}">グー</a>
  <a th:href="@{/jankengame(hand='Choki', userName=${userName})}">チョキ</a>
  <a th:href="@{/jankengame(hand='Pa', userName=${userName})}">パー</a>
</div>

👉 th:href="@{...}" を使うと、現在の userName をパラメータとして自動的に引き継ぎながらリンクを作ってくれます。

③ 対戦結果の表示

<!-- janken モデルが渡されている時（手をクリックした後）のみ表示 -->
<div class="result-box" th:if="${janken}">
  <p>あなたの手: <strong>[[${janken.myHand}]]</strong></p>
  <p>相手の手: <strong>[[${janken.cpuHand}]]</strong></p>
  <p class="result-text">結果: [[${janken.result}]]</p>
</div>

👉 [[${janken.myHand}]] と書くと、Java側の janken.getMyHand() を自動で呼び出して表示してくれます。

6. 課題の「受け入れ基準（AC）」との完全対応表

基準 動作シナリオ なぜこのコードで達成できるか？
Task 1
[AC1]		 トップで taro と入れて参加 → Hi taro と表示される index.html から POST で userName を送信し、Controller が ModelMap に詰めて Thymeleaf の [[${userName}]] で描画されるため。
Task 1
[AC2]		 別タブで直接 /janken を開く → Hi taro は表示されない @GetMapping("/janken") は userName を ModelMap に入れないため、th:if="${userName}" の条件が不成立になり非表示になるため。
Task 2
[AC]		 グー・チョキ・パーをクリック → 「あなたの手」「相手の手」「結果（勝ち・負け・あいこ）」が表示 /jankengame?hand=... で受信した手を Janken クラスに渡し、ランダムな相手の手と勝敗を計算して janken.html に反映されるため。
発展課題 CPUの手がランダムに出る Janken.java 内で new Random().nextInt(3) を使って毎回3つの手から抽選しているため。
